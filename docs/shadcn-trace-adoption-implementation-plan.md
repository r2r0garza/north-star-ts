# PR113 Trace adoption: requirements and implementation plan

## Scope and authority

This is the Requirements and Planning deliverable for implementing `.plan/113-shadcn-trace-adoption.md`, all phases A–E. It is a plan, not an implementation report. Source and tests were inspected on branch `experiment/rebuild-orchestration` at baseline `f36e975`; the working tree was initially clean. No application code was changed and no tests or build were run in this planning step.

Adopt the installed Trace primitives for agent action surfaces only. Preserve application-owned models, ordering, orchestration, approvals, data interpretation and resource lifecycle. The smallest approach is to replace presentation in existing components, keep the workflow adapter separate, and share only the duplicated read-only todo presentation. Do not introduce AI SDK integration, services, persisted disclosure state, dependencies, feature flags or parallel legacy/new renderers.

Phase E means coordinating the Trace detail/body seam with PR114, not implementing all of `.plan/114-shadcn-code-block-adoption.md`. PR113 must work independently with its existing argument/output bodies. PR114 owns Code Block chrome, copy behavior and payload-specific tests.

## Ordered implementation tasks

### Phase A — primitive compatibility and core tools

First add focused primitive and tool-group fixtures using the existing Vitest/happy-dom, React `act`, `createRoot` and IPC-mock patterns. Correct Trace's local cn import and Radix animation selectors after confirming the mismatch; preserve its height bridge and shared Collapsible. Prefer a static action icon plus the existing title shimmer as the sole running treatment, and verify reduced motion rather than adding a spinner.

Next add small presentation-local status/summary formatters in `tool-group.tsx`. Separate approval pending from active execution and implement the AC3/AC4 precedence/wording without touching ToolUse/deriveLabel. Compose Trace → controlled group disclosure → nested Trace → controlled keyed tool disclosures. Do not pass Base UI render/keepMounted props or nest buttons in TraceCollapsibleTrigger. Leave arguments, Bubble/pre results, subagent parsing, interrupted prose and media gating intact. Run tool-group, primitive, media, approval and transcript regressions before expanding scope.

### Phase B — live activity and delegated summaries

Replace only the two live Marker placeholder locations with noninteractive Trace/TraceLine parts, retaining existing conditional priority and memo/scroller structure. Replace SubagentResults cards with nested keyed Trace disclosures and wrapping detail metadata. Map current completed/failed/stopped explicitly (stopped settled with visible label), recognize active/pending string states without deriving new execution facts, and use neutral unknown-state fallback. Keep navigation outside the trigger. Add AC8/AC9 tests.

### Phase C — workflow step activity and tool disclosures

Retain the ordered list and the separate workflow message adapter. Introduce the minimum local keyed step-activity composition needed to own controlled outer disclosure state and the existing message polling outside unmounted content. Use activity.id, not workflow array position, as identity; reset state naturally when a different run/step identity is mounted. Key call disclosures by call.id (within stable message identity) and keep manual toggles across refreshed message objects. Do not reset choices from status changes.

Migrate the existing pairing test before removing its native-disclosure assumptions. Preserve response arrays, callIds/orphan filtering and exact strings; no buildTimeline or ToolGroup reuse. Use existing structured-error detection where appropriate for presentation, not response parsing or data replacement. Leave calls with no response in active work running/unresolved rather than declaring interruption from absence. Preserve existing polling and task subscription behavior, even with the outer disclosure closed. Avoid keeping media/output trees mounted with forceMount; hoist data ownership instead. Do not modify Objective, Outcome or run-control logic. Add all AC10/AC11 status, refresh, control and pairing cases.

### Phase D — shared read-only todos

Add `src/renderer/src/components/todo-trace-list.tsx` as a presentation-only component accepting `{ itemId, content, status }` rows. Keep ul directly containing li, with noninteractive Trace rows inside; use wrapping/whitespace preservation for full prose. A narrow completed-strike-through option can preserve the existing active/historical difference; do not add data fetching, task ownership or handoff logic. Replace both existing status/icon implementations, remove only newly unused imports/constants, and retain each container's compact text scale. Update marker-specific tests without weakening lifecycle assertions, then add shared/historical/handoff coverage.

### Phase E — payload coordination and final integration

Review the Trace disclosure/body seam in tool-group and StepTranscript against PR114. Keep current pre/Bubble bodies if PR114 has not landed; if payloads have independently migrated by implementation time, retain their component composition without rewriting their adapter or copying behavior. Document that PR114 can later replace only argument/result bodies with compact Code Blocks. Do not migrate Markdown, Git errors, approval payloads or Mermaid under this assignment. Run the complete verification sequence below; clean only imports made redundant by PR113, without deleting Marker or adding a permanent compatibility renderer. Roll back a regressing phase rather than shipping both implementations.

## Assumptions and resolved ambiguities

The source spec's phrase “existing active-step behavior” does not imply auto-opening: inspected RunDetail has no open prop on activity details, so retain closed initial state for active as well as settled steps. User choices then survive refresh. Preserve polling separately from visibility because native details currently mounts StepTranscript even when closed.

Preserve consumer-specific todo typography/strike-through rather than silently changing completed historical snapshots. An optional presentation flag is justified solely for this existing difference; the shared component still receives no domain services or callbacks.

Preserve current output information and existing available metadata, not incidental mounted-DOM counts. Workflow response payloads remain uncapped, unlike ordinary tool/delegated output. Account/model context is already visible; use only provided skill/agent values where displaying that required context, with no new lookup or synthetic metadata.

Current subagent contracts return completed/failed/stopped, but renderer strings may be unknown or active/pending. Keep raw status visible, map only recognized states, and never treat an unknown value or stopped as automatic failure. No contract expansion is required.

“All phases” refers to PR113 A–E; implementing all of PR114 is outside this objective. No credentials or external access are required for planning. No unresolved blocker was identified. CSS/runtime behavior remains to be verified during implementation, not asserted by this plan.
