# PR106.7: Refocus, follow-up proposals, and seat memory with provenance

> Status: **PLANNED**. Seventh slice of `106`. Keeps long runs on-mission, and lets seats accumulate
> "tribal wisdom" without letting bad ideas spread unchecked. Three pieces:
> **Refocus** (walk the intent chain and re-ask "is this aligned?"), **follow-up proposals** (a place
> for good ideas that are out of scope), and **seat memory** (lessons inherited across seat generations,
> with provenance, review, and retraction).

## Goal

Fight the three failure modes from the transcript at the altitude where they happen:

- **Doghouse → moonbase.** Each step is locally defensible, but the sum is something nobody asked for.
  → Refocus + proposals.
- **Recursive proof loop / bureaucracy.** Polishing the proof or adding checks after the work is done.
  → Refocus includes "the slice is done; stop" framing, plus `106.3` proof freeze and `106.8` detectors.
- **Mind viruses.** A bad lesson written once gets taught to every future agent. → Seat memory
  provenance, review, retraction, and contact tracing.

## Refocus

**Intent chain** (`src/main/mission-control/intent-chain.ts`): for any seat turn in a Mission Control
run, assemble, bottom-up:

```text
You are working on:   slice  "invoice model" — goal, acceptance ids, OUT OF SCOPE list
which serves:         mission "M1: invoices" — outcome
which serves:         initiative "v1.0 of billing" — intent
Definition of done at your altitude: …
Your seat: builder@implementation — charter (1–2 lines)
Question: Is what you are doing right now necessary for the acceptance criteria above?
If you want something not listed, record it with propose_followup and continue the slice.
```

Bounded (≤ 2 KiB rendered; long fields truncated with ids preserved). Deterministic, no model call.

**Delivery triggers** (each a context-section injection into the seat's next turn, not a user message):

1. Session start and every playbook step kickoff (static, replacing `106.3`'s placeholder).
2. **After compaction**: when the conversation summary service (`019`) compacts a seat's conversation,
   the next turn gets the chain. This matters most, because compaction is exactly when the local picture
   takes over.
3. **Interval**: every N agent turns in the same step (initiative setting, default 12).
4. **On drift signal** from `106.8` detectors (edits outside touch hints, proof edits after acceptance,
   message ping-pong, and rising diff footprint versus spec size). The chain is prefixed with the specific
   signal ("You have modified 14 files outside the slice's expected area").

Refocus never blocks or cancels. It reframes. Repeated drift after refocus escalates via `106.8`.

## Follow-up proposals

- Tool `propose_followup(title, rationale, suggested_altitude: slice|mission|initiative)`: available to
  every Mission Control seat. It creates a `plan_proposals` row (`106.6`) of kind `followup`, anchored to
  the current slice, and returns "recorded — continue with the current slice."
- The Navigator surfaces follow-ups to the lead at mission review (`after_all_slices`) and to the user in
  the proposals inbox. Accepted follow-ups become slices in a *later* mission by default, never the
  current one without an explicit choice.
- This gives the "should the doghouse have a light?" instinct somewhere to go instead of getting built.

## Seat memory

**What it is:** short lessons attached to a *seat* (not a session, not an agent file), injected into
every future session in that seat, across initiatives using the same rig. Example: `qa@implementation`
learns "the payments e2e tests need `STRIPE_MOCK=1`."

**Why not reuse the automatic memory skill files as-is:** the background memory service writes
workspace/global `memory-*` skills without per-note provenance or retraction. Seat memory needs both, so
it uses SQLite rows and **reuses the memory service's extraction/validation pipeline** (candidate
extraction after a turn, injection-safety checks) with a new `seat` scope target.

```sql
CREATE TABLE seat_memories (
  id              TEXT PRIMARY KEY,
  rig_id          TEXT NOT NULL REFERENCES rigs(id) ON DELETE CASCADE,
  seat_key        TEXT NOT NULL,          -- address within the rig (survives agent swaps)
  content         TEXT NOT NULL,          -- ≤ 500 chars
  kind            TEXT NOT NULL,          -- lesson | convention | pitfall
  status          TEXT NOT NULL,          -- pending_review | active | retracted
  origin_session  TEXT,                   -- seat_sessions.id
  origin_slice    TEXT,                   -- slices.id
  origin_turn     TEXT,                   -- messages.id
  derived_from    TEXT,                   -- another seat_memories.id (propagation link) or NULL
  created_at INTEGER NOT NULL, reviewed_at INTEGER, retracted_at INTEGER, retract_reason TEXT
);
CREATE TABLE seat_memory_exposures (      -- contact tracing: who has seen what
  memory_id  TEXT NOT NULL REFERENCES seat_memories(id) ON DELETE CASCADE,
  session_id TEXT NOT NULL,
  injected_at INTEGER NOT NULL,
  PRIMARY KEY (memory_id, session_id)
);
```

**Rules:**

1. **Write path:** the memory service's post-turn extraction, pointed at seat sessions and Mission
   Control workers, produces candidates. New seat memories start `pending_review` by default (setting:
   "auto-activate lessons," off by default), and they're never written by a model tool directly
   (consistent with `MANAGED_MEMORY_WRITE_ERROR`).
2. **Read path:** active memories for the seat, capped (top 20 by recency and use), injected as a context
   section after the charter. Every injection records an exposure row.
3. **Propagation is explicit.** A lesson learned by one seat can be **shared** to another seat or pod
   only by user action or by a lead with `revise_plan` rights via proposal. Sharing creates a new row with
   `derived_from`, so spread is traceable. There's no automatic cross-seat copying, which closes the
   "picked it up from somewhere else" route.
4. **Retraction = vaccine + contact trace.** Retracting a memory (user action) marks it and all
   `derived_from` descendants as `retracted`, lists the affected sessions from exposures, and sends each
   *active* affected session a `kind=alert` correction message (`106.4`): "Earlier guidance '…' is
   retracted because …; do not apply it." Rotated sessions need nothing: their successors no longer get
   the note.
5. **Rig export** optionally includes active seat memories (off by default), with provenance stripped to
   "imported."

## UI

- Seat editor (`106.1`) gets a **Memory** tab: pending review (approve / edit / reject), active,
  retracted; each with origin link (slice + transcript turn) and exposure count; Share and Retract
  actions; a lineage view for `derived_from` chains.
- Initiative view: "Pending lessons (n)" badge.
- Transcript: injected Refocus and memory sections render as collapsed system chips (the same treatment
  as other context sections), so the user can see what the agent was reminded of and when.

## Acceptance criteria

- After a forced compaction mid-slice, the next seat turn contains the intent chain.
- An agent that proposes an out-of-scope idea via `propose_followup` gets it recorded and anchored, and
  the current slice's scope is unchanged.
- A lesson learned in initiative A appears in the same seat's session in initiative B only after
  approval.
- Retracting a shared lesson retracts its descendants, notifies exactly the active exposed sessions, and
  removes it from future injections.
- No tool can write seat memory directly.
- `pnpm typecheck`, focused tests, and `pnpm build` pass.
