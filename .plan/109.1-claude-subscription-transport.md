# PR109.1: Claude subscription request-scoped transport

> Status: **COMPLETED — personal-account macOS transport scope** (2026-10-08). Final scope/acceptance decision is recorded below; earlier open-gate notes are historical. Required transport slice for v1, not provider or release enablement. Windows/Linux/package/service/integration qualification remains in 109.2; broader authentication and managed-policy support remains in 109.4.
> Contract and pinned source references: [109 umbrella](109-claude-code-subscription-experimental.md).

## Objective

Implement an independently cancellable model transport using the unmodified official Claude Code executable. Every host model attempt gets fresh history replay, private request files, inert MCP inventory, one upstream admission, authoritative SSE capture and bounded teardown. North Star remains the agent.

## Proposed file boundaries

Create focused modules under `src/main/agent/providers/claude-subscription/`: `client.ts`, `request.ts`, `history.ts`, `stream-json.ts`, `admission.ts`, `mcp.ts`, `setup.ts`, `model-catalog.ts`, and `errors.ts`, with adjacent tests/synthetic fixtures. Consolidate small modules if that avoids empty abstractions.

Reuse `LlmClient`, `hostCliEnv`, `captureProcess`/process supervision and tool argument replay conventions. Do not reuse `runClaudeCode`'s native session behavior or permissive parser. Changes to shared supervision should be narrowly justified and regression-tested.

## Task 1: Lock the request and history contracts

**Targets:** new `request.ts`, `history.ts`, tests; inspect `providers/index.ts`, `context/context-builder.ts`, `tool-call-arguments.ts`, `title.ts` and all `createCompletion` callers.

Validate the actual host surface before allocating a child/listener: model, messages, function tools, stream, supported stream usage options, output cap spellings, title reasoning effort and auxiliary fields. Required structured output must be deliberately translated, not discarded. Unknown/unsupported inputs fail locally without generation. Sampling/effort policies must be explicit and model-qualified.

Map tools to native names with a request-local reversible mapping. Include `mcp__north_star__` in native name-length checks; do not copy Hermes' 50-character limit without adjusting for prefix length. Reject duplicates/collisions and malformed schemas instead of silently renaming. Qualify schema normalization for Anthropic restrictions without changing host handler validation. Use the same advertised schema in MCP and native extra body.

Preserve historical call IDs/names/arguments, including calls outside today's inventory after progressive discovery or provider switching. Follow North Star's existing malformed-argument replay conventions; do not hide invalid new model tool input as an empty executable object. Unknown output tool names never become privileged native tools.

Preserve ordering and provenance envelopes. Leading system/developer text goes to the system file; misplaced/nontext system content fails rather than elevating history. Convert assistant text/tool_use and tool-result user blocks, preserving available errors/media. Merge adjacent user/results so parallel results remain one coherent queried frame. Reject empty history and assistant-prefill endings.

Support native base64 images from current attachment parts; never fetch remote URLs. A remote URL needs a verified North Star vision-tool hint or explicit unsupported error, not Hermes' tool name. No native signed carrier restoration in v1.

**Acceptance:** deterministic fixtures prove ordinary/multi-turn replay, parallel tool results, steering after results, summary boundaries, removed tools, malformed input, images and no trust promotion. Unsupported requests start no child or server.

## Task 2: Build an inert inventory, not another execution bridge

**Targets:** new `mcp.ts` and tests; inspect existing `agent/mcp-server/` lifetime/auth patterns and MCP SDK APIs.

Prefer a separate request-scoped loopback Streamable HTTP server in the main process. Expose only current tool descriptions/schemas. Every tools/call returns a fixed inert error without importing or invoking the host dispatcher. Use an unpredictable route/capability, strict Origin/path validation and private per-child config. No execution-capable CLI bridge grant, external server proxy, native built-ins or host tool implementations are reachable here.

Early qualification must prove the official CLI accepts this inventory and produces the expected names with strict MCP configuration. If HTTP inventory is incompatible, implement an explicit packaged stdio helper and update build/resource configuration with Electron/ASAR tests; never assume system Node or Python is installed. This fallback is a qualification decision, not an excuse to run host tools inside Claude Code.

**Acceptance:** tools/list matches the validated manifest; arbitrary tools/call attempts have zero host effects; unrelated MCP configuration does not load; failure/cancel removes the inventory listener.

## Task 3: Implement one-request admission and authoritative response capture

**Targets:** new `admission.ts`, response capture helpers and tests.

Bind `127.0.0.1` on an ephemeral port with cryptographic per-request route. Atomically admit one POST to its exact `/v1/messages` path, permitting only query parameters verified against the CLI. Reject other methods/paths, Origin-bearing browser requests and subsequent attempts. Consuming admission begins before forwarding, so failed attempts cannot silently retry upstream. Keep the listener able to reject recovery until teardown.

Production upstream is fixed HTTPS `api.anthropic.com`, with redirects disabled. Test-only dependency injection can use loopback HTTP fixtures. Normalize framing and hop-by-hop/transfer headers; exclude proxy authorization. Forward native authorization/identity in memory only. Never log headers, random route, raw bodies, account email, bearer material or native settings.

Stream bytes back with backpressure. Capture Anthropic SSE with incremental UTF-8/frame parsing and indexed block state: message_start, text/thinking/signature/tool JSON deltas, block stops, message_delta usage/stop details, message_stop and errors. Validate complete block/JSON state, terminal stop reason, finite nonnegative input/output usage (zero is valid), and bounded frames/error bodies. Malformed, missing terminal, transport disconnect and incomplete tools remain failures even if native later synthesizes a result.

Normalize prompt tokens as uncached + cache-read + cache-write exactly once; retain safe cache details and request ID/status/admitted/blocked counts. Capture native costs only as unverified list-price estimates when valid, never actual subscription charges. No request-body restoration or cache rewriting in this slice.

Explicitly decide proxy support because the relay opens upstream sockets. Implement tested HTTPS CONNECT with TLS validation and NO_PROXY semantics, or fail clearly for unsupported proxy configuration. Do not silently connect directly or assume global fetch respects the CLI's proxy environment. Bound connection and read-idle waits, terminate on abort and avoid unbounded response buffers.

**Acceptance:** simultaneous admissions/recovery attempts produce exactly one upstream request; auth headers arrive but never appear in logs; bytes stream correctly; first-response errors/status/usage outrank native recovery; cancellation closes sockets. Include split UTF-8/SSE, multiple blocks, empty-argument tools, zero usage, malformed JSON, refusal, truncated stream, backpressure and redirect/proxy tests.

## Task 4: Private environment, files and replay process

**Targets:** new `client.ts`, `setup.ts`, `stream-json.ts`, `errors.ts`; existing `env/host-cli-env.ts`, `env/spawn-util.ts` only if required.

Resolve a real executable from the host environment/install paths, using argv arrays rather than shell interpolation. Handle Windows npm shims deliberately. Use one verified stable private app-data transport CWD outside any workspace/project tree; reject unexpected symlinks/untrusted existing state. Keep disposable system/settings/manifest/MCP files in separate private request directories (0700 directories/0600 files where supported).

Guard the fully merged host/login-shell environment before any probe/spawn. Reject inherited Anthropic API key/auth token/base URL/cloud-backend overrides selecting another route; errors name variables, never values. Remove/replace provider-owned extra-body/effort/config injection. Preserve user privacy opt-outs; disable auto-updater/feedback and native retry/compaction/tool-search/token-reminder ownership knobs. Default nonessential traffic opt-out for v1 and document discovery fallback impact. Do not open native credentials or add a generic telemetry settings system.

Supply system content by file and validated generation/tool body through private settings `env.CLAUDE_CODE_EXTRA_BODY`. Set output cap consistently with `CLAUDE_CODE_MAX_OUTPUT_TOKENS`; map supported effort to both native extra body and `--effort`. Preserve native auth/identity fields.

The qualified invocation uses print mode, stream-json input/output, verbose/partial messages, `--tools ""`, system prompt file/settings, empty setting sources, strict private MCP config, disabled slash commands, `--max-turns 1`, `dontAsk` and no session persistence. Verify flags and native project/skill/hook isolation on installed versions; do not claim empty setting sources alone removes all contextual behavior.

Replay assistant frames directly. Historical user frames use `shouldQuery:false`; await only their non-error zero-turn result. Reject generation during replay or premature exit. Final user/result frame alone queries, then close stdin. Separate replay acknowledgements from final result accounting. Use bounded replay/init/read-idle waits without a short total timeout that kills healthy thinking.

**Acceptance:** replay never admits an upstream generation until the final frame; settings avoid large argv/env limits; workspace files/native project config and unrelated tools are not loaded; malformed stdout is a protocol failure, never assistant text.

## Task 5: Completion and cancellation compatibility

**Targets:** new client/parser/error tests; shared stream/retry tests where necessary.

JSONL parsing handles split UTF-8, CRLF, multiple events per chunk and final lines without newline, with bounded pending lines and sanitized errors. Stream text only once; compare final authoritative text with the emitted prefix and fail on inconsistent rewrites. Thinking uses reasoning fields, never ordinary assistant text.

Publish executable tool calls only after complete upstream response/usage, the expected native final result and an accepted process exit boundary. Accept qualified complete-tool `error_max_turns`/exit 1 and known locally denied recovery after completed first response; reject arbitrary nonzero exits. Refusal clears executable tool calls; output/context-limit truncation cannot publish incomplete calls. Upstream capture is authoritative over synthetic CLI recovery.

Support AsyncIterable OpenAI-shaped chunks for `stream:true` and aggregate `choices[].message` for absent/false stream. Read abort signal from positional options `rest[1]`. A cached client supports independent requests; no single shared process/cancel state. Iterator return must abort immediately even if next is pending—an async-generator finally alone cannot guarantee this.

Idempotent cleanup covers success, user Stop, stalls, spawn/parser/upstream errors, early consumer return and app shutdown: abort sockets, terminate process group/tree, close stdin/pipes, stop inventory/relay, remove request files and listeners/timers. Follow Windows tree termination and POSIX detached group patterns. Add finite bounds for nonstream auxiliary callers without a signal.

Use North Star `.status`/`.code`/headers for errors. Missing CLI, incompatible version and conflicting environment are deterministic setup failures, not automatically retryable 503s. Preserve genuine upstream auth/billing/rate/overload/server statuses and Retry-After. Protocol failures have explicit classification; cancellation is not a provider fault. No internal generation retries.

**Acceptance:** streamed/nonstreamed fixtures agree; failures do not execute tools; stalled/early-return/concurrent requests clean independently; diagnostics contain no secrets. A failed attempt is visible to North Star's retry coordinator.
