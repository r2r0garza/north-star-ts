## Scope and ownership

The response SSE capture owns ordered native blocks, including opaque thinking signatures and redacted-thinking data. The Claude adapter emits a private Symbol-keyed carrier on its terminal chunk (or non-stream message). CompletionRound retains it for the successful attempt; the agent persists it on final/refusal/tool-call assistant rows and carries it into the in-memory follow-up. The append-only v66 migration adds `messages.native_assistant`; existing rows remain canonical-only. Repository reads validate and clone carriers; ContextBuilder attaches them privately. The renderer message-list IPC explicitly omits the carrier, and Symbol keys do not serialize onto foreign-provider JSON wires. No reasoning/signature data is appended to visible assistant text or diagnostics.

Version 1 is scoped to `claude_subscription` and an explicit dated/family Claude model ID. Mutable aliases (`sonnet`, `opus`, `haiku`) deliberately do not receive reusable carriers: their resolved identity can change. Cross-model reuse is unsupported. Carriers are limited to 4 MiB and known native block fields; unknown versions, providers, blocks, metadata fields and missing thinking signatures fall back to canonical history.

Reuse requires exact visible-text and ordered tool-ID/name/parsed-input equivalence, plus a SHA-256 fingerprint of the complete preceding canonical conversation frames. This invalidates older-history edits, deletions and summary replacement as well as modifications to the assistant itself. The fingerprint excludes private reasoning/signatures and transport-only query flags. No whitespace normalization is allowed for text. Existing parsed-input semantics apply to arguments; historical call/result validation runs before carrier substitution. Canonical content/argument transforms cannot be bypassed by a carrier. Tool-result media differences in the prefix also invalidate later carriers (including the intentionally transient screenshots deferred to 109.5).

Installed-CLI loopback qualification exposed a native requirement: replay assistant frames must include the matching `message.model`, or Claude removes thinking blocks. The adapter now supplies that model identity. Synthetic signatures prove byte transport, not vendor acceptance of fabricated signatures.

## Queried results and cache decision

The admission seam buffers at most 32 MiB and applies independently tested result restoration. Restoration requires unique, ordered IDs and equality of all result fields, all media, protected additions and cache metadata. Its sole equivalences are scalar text versus one plain-text block and an absent `is_error` versus boolean false. Invalid boolean flags, account-reminder-like additions, substrings, prefixes/suffixes, duplicate/reordered IDs and cache directives never establish a match. A mismatch forwards the original request bytes and emits only a fixed diagnostic code. Canonical DB results are never rewritten.

No annotation-stripping, first-turn reordering or cache-breakpoint relocation is enabled. No specific native annotation layout has sufficient byte-level qualification to justify that rewriting. Exact requests retain their bytes, marker counts, TTL ordering, system/tool marks and native identity; unknown layouts forward unchanged. This is the conservative Task 3 decision, not a claim that cold/subsequent prefixes have identical cache breakpoints or that native cache optimization has shipped. Future relocation needs its own pinned layout fixtures and explicit qualification; it is not silently enabled by CLI version detection.
