# PR5.1: Stop in-flight tool calls — ContainerEnvironment in-container kill

> Status: **NOT STARTED** — follow-up split out of `.plan/005`, which fixed the LocalEnvironment
> case (process-group kill on the detached host child). This covers the container backend, which
> needs a different mechanism.

## Context

`ContainerEnvironment.exec` (`src/main/agent/env/container.ts`) runs the model's command by
spawning a host `docker exec` / `podman exec` client and capturing its output through the shared
`captureSpawn` (`env/spawn-util.ts`). The abort signal is wired through, but on Stop/timeout we
SIGKILL only the **host exec client** — the actual process **inside the container keeps running**.
Unlike the local case, we deliberately do NOT pass `killGroup` (the exec client is not a detached
process-group leader, and the in-container process isn't in the host's process group at all).

So pressing Stop on a long container command (a build, a test run) ends the turn but leaves the
work churning inside the container until it finishes or the container is disposed.

## Open questions to resolve before building
1. **Kill mechanism.** Options:
   - Track the in-container PID (e.g. wrap the command to `echo $$ > /tmp/pidfile &` or run it
     under a known wrapper) and on abort issue `runtime exec <name> kill -KILL <pid>` /
     `kill -KILL -<pgid>`.
   - Marker-based: prefix each exec with a unique env var / arg marker, then on abort
     `runtime exec <name> pkill -KILL -f <marker>`. Simpler but relies on `pkill` being in the
     image and risks matching the wrong process.
   - Per-command ephemeral container (`run --rm` instead of `exec` into the shared one) so kill =
     `runtime kill`/`rm -f`. Cleaner kill, but changes the warm-container model.
2. **Image assumptions.** `pkill`/`kill` availability varies by base image; pidfile approach is
   more portable but more plumbing.
3. **Interaction with dispose.** `dispose()` already `rm -f`s the container; confirm the abort
   kill and dispose don't fight, and that an aborted command doesn't wedge the shared container.

## Out of scope
- The LocalEnvironment case (shipped in `.plan/005`).
- Container lifecycle / warm-container changes beyond what the chosen kill mechanism requires.

## Verification (when built)
- Run a slow forking command in a container session, press Stop → verify (via
  `runtime exec <name> ps`) the in-container process tree is gone, the turn ends with
  "⏹ Stopped by user.", and no further round-trip starts.
