## Objective

Expose `claude_subscription` as **Claude Code Subscription - Experimental** without mistaking a local model subprocess for an autonomous CLI agent. Integrate keyless setup, models, canonical context, auxiliary calls and runtime overrides; qualify ownership and cleanup before release.

## Initial authentication scope — 2026-10-08

API-key, Team/Enterprise, token-only and unknown/new auth configurations are deferred to [109.4](109.4-claude-code-authentication-and-managed-policy.md), including policy-preserving routing and separately authorized work-machine qualification. An enterprise test account is not required for personal-scope integration; do not claim that synthetic status fixtures resolve account-metadata freshness or organization-policy compatibility.

## Task 2: Keyless client routing and host-owned attempts

Missing executable/incompatible CLI/conflicting env are deterministic setup failures even though Hermes maps missing CLI to 503; North Star's current 5xx classifier would retry that. Preserve genuine upstream status/Retry-After and normal request permits/attempt rollback. One host attempt admits at most one upstream Messages request.

**Acceptance:** resolveLlm/hasActiveProvider work without secrets; normal runAgentLoop owns tools/history/retries. Existing autonomous CLI and API accounts are unchanged. Test same-account concurrency and Stop isolation.

## Task 3: Atomic setup, safe IPC and practical catalog

**Targets:** `src/main/ipc/provider-handlers.ts`, `src/preload/index.ts`, renderer type exports, provider `setup.ts`/`model-catalog.ts`, adjacent/new handler tests.

Bound executable/version/auth status probes; return only installed/version/logged-in/compatibility state and safe hints, not raw credential or account-email output. Installation/login instructions are user actions; no automatic installation, auth or update.

Before providers:create writes state, validate provider/environment/CLI version/auth and obtain a usable seed/fallback catalog. Make account and model insertion atomic after preflight. Main handlers reject custom upstream/key configuration for this provider, rather than relying on hidden UI fields. Failure cannot leave a half-created enabled account. Keep recheck available after login changes.

Model discovery correlates initialize control responses through a deny-all Messages gate; settings/model refresh never query a generation. On timeout/unsupported handshake preserve previous/manual entries or a verified seed catalog, with explicit fallback status. models.list uses discovery/catalog without pretending an HTTP models endpoint exists. Do not treat picker visibility as proof of entitlement, or assert reference models are currently available.

Store IDs/names using existing models rows; allow manual IDs. Use route IDs consistently for native argv and context metadata. Unknown routes have conservative budgets; explicit/verified [1m] selection is necessary for long context, not a family-name guess. No broad model metadata schema is needed until demonstrated. Multiple configured entries share official CLI login; distinct auth profiles are out of scope.

**Acceptance:** local setup failures are actionable and secret-free; create is atomic; discover proves zero upstream Messages requests; discovery failure retains usable configured catalog and manual entries.

## Task 5: Refusal and reasoning semantics

**Targets:** `src/main/agent/model-request-retry.ts`, `src/main/agent/index.ts`, retry/agent integration tests including `tool-error-feedback.integration.test.ts`; provider response adapter.

Current stream consumption marks refusal/reasoning fields as recognized but does not retain/display their content. Current loop validation makes only empty content_filter terminal and can otherwise recover text-encoded calls. Introduce a narrow refusal contract retaining safe explanation and finish reason. A refusal is terminal, displayable/persistable and never an empty-answer retry.

Suppress both structured tool calls and text-extracted markup when refused, including a refusal explanation quoting tool syntax. Do not let extractTextToolCalls resurrect a cut-off/denied call. Test textful/textless refusals, partial calls, markup and existing providers' behavior. Preserve successful ordinary output and output-limit handling.

Thinking never goes into ordinary assistant text. V1 may preserve recognized reasoning diagnostics without creating a new reasoning UI/persistence framework; state that this is not signed-history parity. Do not claim mapping reasoning_content alone displays or persists it in North Star today.

**Acceptance:** refusal makes no host tool effects, needs no repeated empty-response requests and remains legible. Reasoning does not leak into final text. Existing text/tool response validation regressions pass.

## Task 6: Context and auxiliary completion compatibility

**Targets:** provider catalog/preflight, `agent/index.ts`, `context/context-builder.ts`/tests only as needed; title tests, summary/memory/background callers found by tracing createCompletion.

ContextBuilder currently budgets optional sections from the configured summarize threshold and replays all history after the summary boundary. There is no existing per-model context-window hook. Do not claim a static model table fixes budgeting. Add a narrowly scoped new-provider preflight estimating canonical history/system/tools plus native overhead and output reserve against verified route limits. Use existing host summarization if available at that seam or fail clearly; never silently truncate canonical history or enable native compaction.

Keep unknown-route fallback conservative/documented, and route/window selection consistent. Verify summary boundaries never omit history without its summary, edits/deletions replay updated history, provider switching ignores native sessions, and attachment/tool media retains available semantics. General context management redesign is outside this slice.

Nonstreaming title requests use reasoning_effort low and no signal today. Trace memory/summarization/background callers before deciding supported fields. Implement their actual stream:false/default request shapes and finite lifecycle bounds. Auxiliary routes remain explicitly selected; subscription default does not silently override other configured providers.

**Acceptance:** title/summary/memory completions use the intended selected account and do not fail due to unsupported shared parameters. Context overflow is clear and host-owned, not native autocompaction or quiet history loss.

## Task 7: Qualification matrix

**Synthetic automated fixtures (no credentials/private trajectories):**

- Parser/replay acknowledgements, malformed stdout, UTF-8 boundaries, init/replay/stream timeouts and output caps.
- Admission atomicity/concurrency, denied native retry/recovery, SSE block completion, upstream failure precedence, zero/cache usage and secret-free logs.
- Inert inventory tools/call denial, strict tool name/schema limits and unknown/removed tools.
- Stream/nonstream equivalence, final result/accepted exit validation, text deduplication and refusal/truncation tool suppression.
- Cleanup on success, spawn failure, stream failure, Stop, idle stall, early return and shutdown, including pending next; independent same-account owners.
- Keyless readiness/routing, atomic preflight/create, migrations/FKs/self-heal, unsupported config rejection, discovery fallback and zero-generation initialization.
- Host tool round-trip with durable assistant/tool rows, host approval denial, custom restrictions, progressive discovery, container tool environment, summary/provider switch/edit history.
- Auxiliary callers, process/seat runtime overrides and portability, refusal markup and existing CLI/API regressions.

**Installed official CLI with synthetic loopback upstream, before paid usage:** qualify exact flags, file-backed extra body/tools/output caps, assistant replay and historical zero-turn results, HTTP inert inventory, strict isolation, initialize with zero generation, complete tool error_max_turns boundary, completed-first-response precedence over denied recovery, cancellation and packaged Electron execution. Test supported desktop platforms rather than extrapolating from macOS fixtures. Record CLI version/platform, sanitized outcomes and known compatibility limitations.

**Version and OS policy:** transport preflight accepts stable Claude Code >=2.1.286 and <3.0.0, not an exact tested-version allowlist. Keep the last tested version/platform visible in qualification evidence, separate from accepted versions; new patch/minor releases remain subject to runtime protocol/isolation checks. Prerelease/new-major support requires review. Windows and Linux support is explicitly deferred until native VM/CI/host runs pass; do not infer support from macOS or parser tests. Windows qualification must verify native executable/PATH handling, private directories/files with effective ACL protection, and descendant process cleanup. Linux qualification must verify native installation/PATH, private permissions and process-group cleanup. Both require installed-CLI loopback isolation/replay/discovery/cancellation before removing the core transport OS gate, followed by a native installed-suite rerun without a platform-policy substitution. As specified in the prerequisite checkpoint above, packaged Electron execution is a separate release gate, not a reason to substitute an OS in core transport tests. A transport-only packaged harness can qualify runtime mechanics before integration; integrated application packaging remains to be qualified after 109.2. No physical hardware is required if suitable native VMs/runners are available.

**Subscription-backed smoke tests require explicit user approval:** bounded text → host read tool → result continuation, host denial, DB-backed second turn, edited/provider-switched history, host summarization continuation and Stop. Confirm admitted counts and observed usage; do not claim actual billing verification. If canonical reconstruction fails without signed replay, promote the necessary correctness portion of 109.3 before release.

Incompatible CLI must fail closed with upgrade/recheck guidance, never quietly select the old autonomous CLI mode. Review applicable vendor terms/support before broad distribution. No unbounded autonomous qualification run.
