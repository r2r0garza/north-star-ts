# Canonical host media v1

Implementation contract for 109.5. `ToolContext.emitImage` remains the only production image side channel. Producers hand the host bounded JPEG bytes and an untrusted caption; the host assigns linkage and immutable app-owned blob identifiers. Existing text-only history is unchanged and never rereads source files.

Persist a versioned descriptor with each successful tool lifecycle result, projected onto its tool message: `version: 1`, opaque `id`, `mediaType: "image/jpeg"`, `width`, `height`, `byteLength`, `sha256`, `order`, `alt`, `createdAt`, `expiresAt`, `toolCallId`, `toolName`. Captions are data, not instructions. Dimensions are validated from bytes, never trusted from the caller. Blob paths are host-derived; renderer requests use conversation/message/media identity, never paths. References are shared by lifecycle and message recovery, not a competing provider-specific image contract.

Limits: 2 MiB per encoded image, three images/6 MiB per tool result, 64 images/128 MiB per conversation, and 30-day retention. Standalone source files are capped at 16 MiB, 24 megapixels and 16,384-pixel edges; normalize locally with orientation, white transparency compositing and first-frame-only animation to JPEG with a 1,568-pixel long edge. Decoders are bounded to two concurrent jobs and 15 seconds, and destroyed on cancellation. No remote fetching, OCR or auxiliary generation. Browser/PDF producers already downscale; storage additionally accepts only supported JPEG frame/scan headers with at most 8,192-pixel edges and 32 megapixels within the encoded-byte cap.

Publish immutable blobs before atomically settling lifecycle metadata. Ignore image callbacks after execution closes or cancellation; failed/error-text/unknown/not-started calls retain no images. Ordered batch projection uses per-call descriptors. Crash-published unreferenced blobs are collected on startup or the next store/delete operation; synchronous main-process publication/settlement requires no grace period. A 1 GiB global retained-byte ceiling supplements conversation quotas. v1 deliberately does not deduplicate: independent opaque blobs simplify ownership, expiry and deletion; SHA-256 verifies integrity, not cross-conversation lookup. Cleanup runs on bounded startup/store operations; no source-file rereads.

ContextBuilder hydrates only surviving tool results linked to assistant calls in the admitted history tail. Emit attributed untrusted text and canonical image_url parts after all tool results in that call group. The same helper projects live continuation and replay. Summary coverage suppresses covered images atomically with text; summaries are textual recall, not retained visual recall. Edits/deletes remove reachable references and prevent lifecycle repair from resurrecting deleted images. Missing/corrupt/expired bytes produce explicit unavailable text, never native CLI recovery. Provider switches replay the same canonical bytes; unsupported vision must fail legibly without silently dropping images or switching providers. Image admission counts image cost rather than base64 as text.

Renderer previews are lazily loaded only for expanded tool results, bounded in dimensions/count, attributed with caption/tool/order, and expose loading/unavailable states. Main-process lookup verifies conversation/message ownership and validates the stored bytes before returning a bounded JPEG data URL. No arbitrary filesystem or remote URL capability is exposed. Legacy tool rows without descriptors continue as text-only capture records.

Qualification must distinguish automated tests, installed-CLI loopback, native packaged decoding/rendering and live interpretation. Live subscription vision requires fresh separate user approval; no distribution checks are implied by build success.
