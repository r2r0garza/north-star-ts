# Handoff: qualify 109.1 transport on Linux and Windows

Prepared 2026-10-08 for another North Star agent session on each native host. This is a qualification runbook, not a new numbered roadmap slice or evidence that either platform already works.

## Goal and current decisions

Before starting 109.2 integration, qualify the existing 109.1 functionality on BOTH native Linux and native Windows. A VM is sufficient; WSL results do not qualify native Windows. Make necessary narrow portability fixes, add regressions and preserve macOS behavior. Complete each platform independently; never enable an untested OS merely because the other passed.

Read [109.1](109.1-claude-subscription-transport.md), especially its final personal-scope acceptance, [109.2 prerequisites](109.2-claude-subscription-integration-and-qualification.md), and [109.4](109.4-claude-code-authentication-and-managed-policy.md). 109.1 is complete only for personal-account macOS transport; the provider is not registered/enabled. North Star owns history, tools, approvals and retries; Claude Code is disposable inference transport, not the autonomous agent. The selected initial display name is Anthropic Subscription - Experimental; some older plan text still uses the former name.

Stable CLI versions >=2.1.286 and <3.0.0 are accepted by version policy; do not replace this with an exact-version pin. Prereleases/new majors remain unsupported pending review. Recorded installed-binary evidence is Claude Code 2.1.286/darwin, Node 24.21.0; synthetic newer-version tests are not newer-binary qualification. Latest baseline: 151 synthetic transport tests, 21 opt-in installed-CLI tests, typecheck, build and roadmap validation passed on macOS. Counts may change: inspect the actual checkout rather than forcing an old count.

Personal v1 accepts the official CLI's reported `loggedIn:true`, `authMethod:"claude.ai"`, `apiProvider:"firstParty"`, `subscriptionType:"pro"|"max"`. The user accepts metadata freshness/check-start limitations for this experimental scope. Retain checks; do not infer policy freedom from absent cache or organization fields. API-key, Team/Enterprise, token-only, unknown auth states and broader provider routes belong to 109.4, not this handoff.

## Safety and workspace preparation

Confirm the checkout includes all transport source, fixtures and plan documents. At handoff preparation much of this feature was untracked on `feat/claude-sub`; a fresh clone of committed HEAD alone may omit it. Ask the user to transfer/commit the intended changes through their normal workflow. Inspect `git status` and preserve unrelated/in-progress edits; never reset/clean the checkout to make tests pass.

Use an ordinary user on an authorized machine with official native Claude Code installed and compatible Node/pnpm plus repository dependencies. Read package scripts/lockfile and follow repository bootstrap conventions. Dependency installation, native rebuilds and CLI installation may require approvals/network access; do not run an automatic vendor update. Record OS version/architecture, Node/pnpm/CLI versions and revision/dirty state, without dumping environment values.

All automated qualification uses disposable synthetic HOME/config directories, synthetic credentials and loopback model responses. Do not open native credential files, copy tokens, reuse native sessions, change system policy or bypass employer restrictions. Do not make live subscription/API inference calls under this handoff; separately approved bounded smoke tests are 109.2. A read-only official auth-status check can be used to inspect personal metadata, but redact email, organization IDs/names, paths and any unexpected fields. Never save raw status, stderr, headers, request bodies, route capabilities or debug dumps to evidence.

## Code to inspect first

`src/main/agent/providers/claude-subscription/` contains `setup.ts`, `managed-policy.ts`, `auth-policy.ts`, `client.ts`, `model-catalog.ts`, `admission.ts`, `mcp.ts`, `sse.ts`, `stream-json.ts`, replay/schema helpers and adjacent tests. Shared process/environment behavior is in `src/main/agent/env/host-cli-env.ts` and `spawn-util.ts`; narrowly regression-test shared changes.

Two production gates currently reject non-macOS: `guardManagedPolicy` in `managed-policy.ts` and `compatibleVersion` in `setup.ts`. The policy guard runs before the version probe. Installed tests on Linux/Windows WILL initially fail at these gates; that is expected, not a reason to delete the checks. Synthetic tests also contain macOS-specific assumptions and must be made intentionally platform-aware.

On a dedicated qualification branch, implement OS-specific safety prerequisites and use a narrowly scoped test-only qualification seam if needed to exercise real native behavior before production enablement. Such a seam must not disable policy/account/protocol/admission checks, silently alter `process.platform`, or expose a production bypass environment variable. Keep qualification status explicit until all required checks pass. Record any test substitutions. Do not label gate removal itself a successful qualification.

## Linux-specific implementation and checks

Verify executable discovery through the host/GUI environment, absolute PATH handling, real executable resolution and argv-based spawning without shell interpolation. Test missing CLI, spaces/non-ASCII paths and failed/version-stalled probes. Preserve login-shell environment guarding and secret-free errors.

Implement conservative Linux managed-policy presence checks for documented system sources, including `/etc/claude-code/managed-settings.json`, `managed-settings.d` and `managed-mcp.json`, plus `remote-settings.json` in the CLI's effective config location. Recheck current vendor documentation and actual native config path; do not assume macOS HOME rules cover every OS/config selector. Presence, unreadability, malformed source discovery and unexpected symlinks must fail safely without reading policy contents. Do not call macOS `/usr/bin/profiles` on Linux. WSL policy inheritance requires its own documented boundary: either reject it explicitly pending qualification or qualify it separately; a Linux VM pass is not WSL evidence.

Verify owner UID and 0700 transport/request directories, 0600 request files, empty private stable CWD outside the workspace, rejected symlinks/untrusted existing state, cleanup on every path and path confinement. Verify cancellation kills the detached POSIX process group including an owned fixture grandchild, not just the immediate CLI, with no leaked listeners/timers/sockets/artifacts.

## Windows-specific implementation and checks

Use a native Windows Node process (`process.platform === "win32"`) and official `claude.exe`. Current discovery deliberately rejects `.cmd` npm shims; retain the clear failure unless deliberately implementing and qualifying shim support. Check per-user installation PATH through the app environment, drives, spaces/non-ASCII names, case handling, real executable paths and argv quoting. Do not substitute Git Bash/WSL to claim Windows spawning works.

POSIX mode bits do not protect Windows secrets. Implement/qualify effective ACL protection on transport root/CWD/request directories and every request file, including creation/inheritance and untrusted pre-existing state. Use owned disposable fixtures to inspect ACLs (for example `Get-Acl`); do not broadly change user-profile ACLs. Test reparse points/junctions as well as symlinks, Windows path confinement and cleanup with open handles. `privateDirectories` currently skips Windows permission/owner verification and its Windows file-path confinement check: these are concrete review/fix targets, not established safe behavior.

Implement presence-only Windows managed-policy checks using current documented system paths (including `C:\Program Files\ClaudeCode` files/drop-ins/MCP) and registry policies at HKLM/HKCU `SOFTWARE\Policies\ClaudeCode`. Qualify registry view/absence/error behavior; inspect only the presence needed for rejection, not policy bodies. Verify effective config-directory/cache selection with USERPROFILE/APPDATA/HOME as applicable. Do not query macOS enrollment or mutate registry/system policy to set up tests; use injectable synthetic policy-discovery fixtures.

Shared supervision currently uses `taskkill /pid <owned-pid> /T /F` for Windows group termination. Prove it terminates an owned fixture descendant tree on cancel/stall/iterator return/shutdown and that termination is bounded when taskkill fails. Never kill unrelated Claude/Node processes by name. Fixture child environments must retain required Windows variables (such as SystemRoot/WINDIR and installation dependencies) while redirecting every HOME/config selector to synthetic state, so tests do not read the real account accidentally.

## Commands: establish baseline, then rerun after fixes

Run from the repository root. These commands do not overcome the current OS guards; capture the initial failures, implement justified fixes, then rerun. Use direct Vitest paths here: historical `pnpm test -- <path>` ran more than the intended selection. DB-dependent tests must use the repository's SQLite wrapper; these transport tests do not need it.

Linux shell:

```sh
git status --short
git rev-parse HEAD
node --version
pnpm --version
command -v claude

pnpm exec vitest run src/main/agent/providers/claude-subscription
NS_QUALIFY_INSTALLED_CLAUDE=1 pnpm exec vitest run src/main/agent/providers/claude-subscription/installed-cli.test.ts
pnpm exec vitest run src/main/agent/env/spawn-util.test.ts src/main/agent/model-request-retry.test.ts
```

Native Windows PowerShell:

```powershell
git status --short
git rev-parse HEAD
node --version
pnpm --version
Get-Command claude -All | Select-Object CommandType, Source
claude --version
pnpm exec vitest run src/main/agent/providers/claude-subscription
$previousQualification = $env:NS_QUALIFY_INSTALLED_CLAUDE
try {
  $env:NS_QUALIFY_INSTALLED_CLAUDE = '1'
  pnpm exec vitest run src/main/agent/providers/claude-subscription/installed-cli.test.ts
} finally {
  if ($null -eq $previousQualification) {
    Remove-Item Env:NS_QUALIFY_INSTALLED_CLAUDE -ErrorAction SilentlyContinue
  } else {
    $env:NS_QUALIFY_INSTALLED_CLAUDE = $previousQualification
  }
}
pnpm exec vitest run src/main/agent/env/spawn-util.test.ts src/main/agent/model-request-retry.test.ts
pnpm run typecheck
pnpm run build
pnpm run verify:roadmap
```

PowerShell external commands do not necessarily stop on nonzero exit: inspect `$LASTEXITCODE` after each command and record failures instead of reporting the last command's success as success for the sequence. Tooling/bootstrap failures are separate from transport failures.

## Required functional evidence on each OS

- Local request validation rejects unsupported fields, malformed history/schemas, auth/environment/proxy conflicts and incompatible CLI before model subprocess/admission startup. Version policy accepts supported stable 2.x without a patch pin, and rejects unsupported major/prerelease banners.
- Historical user frames acknowledge with zero turns and zero upstream requests; assistant replay is direct. Parallel results, removed historical tools and steering preserve IDs/order/content. Repeated matching init inventories pass; inventory drift fails before generation.
- Private settings carry matching native/MCP tool schemas, output caps and supported effort. Inert HTTP tools/list matches the request; arbitrary tools/call has no host effects. No native executable tools, foreign MCP, hooks/plugins/skills or workspace instructions load. Isolation controls must positively detect their harmless contamination.
- Exactly one upstream Messages request is admitted; subsequent exact-path attempts are denied. Production upstream remains fixed HTTPS with redirects disabled and unsupported proxies rejected. Auth forwarding stays memory-only and absent from logs; synthetic tests use synthetic credentials only.
- Text/tool streaming and nonstreaming agree. SSE/JSONL UTF-8, terminal block/tool JSON, usage/cache buckets, refusal, truncation, unknown tools, split chunks and backpressure behave as specified. HTTP 429/Retry-After retains first-response precedence despite inherited retry knobs.
- Real installed CLI empty-text `end_turn` and `max_tokens` fixtures trigger denied recovery in both stream modes: one upstream request, `recoveryBlocked:1`, protocol failure, no executable tool calls. Baseline text finalization is success/exit 0/one turn; complete-tool boundary is `error_max_turns`/exit 1/two reported native turns despite one request. If a newer binary differs, investigate and record safe numeric/subtype evidence before changing acceptance; never accept arbitrary exits merely to turn tests green.
- Discovery uses correlated initialize only, with zero Messages admitted/upstream; malformed/unusable catalogs fail without silent fallback. Account probe errors and cached policy block both entry points before listeners. Loopback tests currently mock personal-account eligibility to permit synthetic API keys; the dedicated real probe case must still reject the API key. Passing this suite is not end-to-end real personal login/entitlement evidence.
- Stop/positional AbortSignal, stalled reads, malformed stdout, spawn failure, iterator return with a pending next, discovery cancellation and shutdown remove owned processes/descendants, sockets, MCP/relay listeners, timers and request files. Stable empty CWD may remain. Concurrent requests clean independently. Add missing native descendant/shutdown/permission assertions rather than assuming existing socket/artifact checks prove them.

Review existing tests against this matrix and add gaps; not every required OS assertion already exists. Keep fail-closed boundaries intact. If isolation/cancellation/policy/ACL behavior cannot be qualified, report the blocker and leave that OS disabled.
