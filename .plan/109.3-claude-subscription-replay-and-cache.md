## Objective and promotion rule

Improve native replay continuity and cache reuse after canonical-history v1 is proven. Do not add Hermes-specific reasoning_details or wire mutation to North Star merely to claim parity. Promote the minimum native-carrier correctness work into v1 only if approved real-service qualification demonstrates that canonical reconstruction cannot continue safely without it. Cache savings alone do not justify blocking v1.

## Task 1: Design lossless, scoped native assistant metadata

**Targets:** provider history/response adapter, `src/main/db/types.ts`, messages repository and tests, ContextBuilder, CompletionRound/stream consumption, `agent/index.ts` assistant/tool persistence. Determine existing metadata capacity before proposing an append-only migration.

Define a versioned provider/model-scoped carrier for ordered native assistant blocks and a canonical projection of visible text, tool IDs, tool names, parsed inputs and order. Preserve signatures only as opaque native metadata, never ordinary assistant text. Bound storage and validate carrier provenance/version before reuse.

Specify how metadata survives stream completion, DB persistence, app restart, ContextBuilder and the next model attempt. Simply adding reasoning_content or reasoning_details to a chunk is insufficient: today's consumer does not persist those fields. Define exact ownership and storage before implementing.

Replay native blocks only if the current projection matches. Edits, deletions, compaction, hooks, tool transforms, provider/model switching or unknown versions invalidate the carrier and reconstruct canonical blocks. Foreign-provider metadata is ignored; cross-model signed replay remains unsupported until separately qualified. Whitespace/normalization equivalence, if allowed, needs explicit narrow tests rather than broad fuzzy matching.

**Acceptance:** unchanged persisted turns retain ordered native blocks across restart; altered projections never restore stale content/signatures; unsupported carriers cannot bypass canonical history or tool validation.

## Task 2: Lossless queried tool-result restoration

**Targets:** provider admission/history helpers and adversarial fixtures.

If native appends per-request annotations to queried tool output, restore host representation only when unique ordered tool-use IDs and exact content/media/error semantics prove the match. Preserve metadata-bearing blocks, cache directives, images and protected text. Missing is_error may be equivalent to false only with protocol-valid boolean rules.

Never pattern-strip account reminders or find host content by ambiguous substrings. Changed IDs/content/media/error semantics, ambiguous marker mapping or unexpected protected additions must forward unchanged and emit a bounded safe mismatch diagnostic. Canonical DB output is never rewritten to match native annotations. Keep restoration independently testable from admission and cache transforms.

**Acceptance:** scalar/list plain-text equivalence is narrowly defined; adversarial prefixes, duplicate IDs, metadata, media and inserted content cannot remove protected material or launder cache marks. Unprovable restoration degrades fidelity/cache reuse rather than turning into destructive rewriting.

## Task 3: Cache breakpoint and first-turn stability

**Targets:** new provider cache-wire helpers/tests, admission transform seam.

Only after byte-level fixture qualification, consider reordering first-turn native annotations and relocating message cache breakpoints onto stable replayed content. Do not modify native auth/identity, unrelated system/tool markers, or arbitrary prompt text. Preserve marker-count limits and native TTL ordering; never increase markers or move a breakpoint later onto unproven content.

Validate protected additions before relocation, including multiple native marks and thinking/redacted-thinking blocks. Keep transforms narrow, version-aware and disableable on unknown layouts. A stable isolated CWD, disabled native token reminders and deterministic request assembly remain the baseline; rewriting is not a substitute for those.

**Acceptance:** cold first turn, parallel tool results, subsequent turns, edited history, client recreation and app restart have stable qualified wire prefixes without content loss. Unknown wire shapes forward unchanged with safe diagnostics.

## Task 4: Measure separately from correctness

Use synthetic loopback fixtures to establish wire continuity, not vendor cache-hit claims. With explicit user approval, compare bounded real multi-turn usage against v1, preserving actual input/cache-write/cache-read/output buckets and admitted request counts. Native list-price estimates are not subscription invoices or verified savings.

Qualification must cover signed replay after supported history transformations and explicitly reject unqualified cross-model reuse. Record CLI version/platform and whether results come from synthetic fixtures or real service. Do not copy Hermes' published cache percentages into North Star acceptance evidence.
