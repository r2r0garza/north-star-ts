# PR109.01: QA write scope and prompt

> Status: **DONE** (2026-10-03). Slice 1 of 6 of [`109`](109-qa-seat-verification-capabilities.md).
> Implements product decisions 1, 2, and 10. `109.02` depends on this slice. Where the build differs
> from the shape below, see **As built** at the end.

## Goal

A QA seat can write acceptance checks, but only in its checks directory. The tools enforce that, not
just the prompt. The QA agent's instructions say to write checks and never product code.

## Proposed shape

### Write scope at the tool boundary

- `ToolContext` gains `writeScope?: { allow: string[] }` (workspace-relative prefixes). It's resolved
  server-side from the seat's role when the phase starts:
  - `qa`: the user story's checks directory (below) and the run's scratch directory;
  - every other role: no restriction (field absent).
- Every write-family tool checks it after `resolveInWorkspace`: `write_file`, `edit_file`,
  `apply_patch`, the filesystem lifecycle tools (create/move/copy/delete), and file-mode mutation.
  Out-of-scope writes return `toolError("out_of_scope", …)` naming the allowed directories, so the
  model can recover.
- The check compares resolved real paths, not raw strings. `../` traversal and symlinks pointing out of
  the checks directory are refused.
- `run_shell` can't be confined by path. The prompt covers it, and `109.02`'s diff report at the test
  step makes violations visible (see the parent's risks).

### Checks directory

- New workspace setting `missionControl.checksDir` (default `.mission-control/checks`), stored with the
  workspace's other Mission Control settings and editable on the Feature home setup section (`106.11`).
- A user story's checks directory is `<checksDir>/<user-story-slug>/`. The slug is resolved
  server-side from the user story, never from the model.
- The checks directory is tracked in git (not ignored), so checks are committed on the user story branch
  and merge with the code.

### QA agent prompt

Rewrite `agents/qa-agent.agent.md`. The bundled-seed refresh (incremental seeding, `12e97fa`) picks it
up, and user-edited copies are left alone. The new prompt:

- keeps the adversarial mindset and the "say what you did not verify" rule;
- replaces "you verify and report; you do not fix" with: you write and run checks; you never edit
  product code; failures go in the proof, not into fixes;
- explains the checks directory and why a write elsewhere is refused;
- describes the workflow the later slices enable (checks first, app via `app_start`, browser for UI
  criteria, evidence saved). Instructions for tools that don't exist yet are added by the slice that
  ships them, not here.

## Tests

- A `qa` seat writing inside its checks directory succeeds; writing to `src/` is refused with
  `out_of_scope`.
- A `builder` seat writes anywhere in the workspace, as today.
- `../` traversal and a symlink pointing out of the checks directory are refused.
- An ordinary (non-Mission Control) conversation is unaffected.
- Seed test: the bundled QA agent contains the new guidance, and a user-modified copy isn't overwritten.

## As built

- **Enforcement** is `writeScopeError` in `src/main/agent/tools/write_scope.ts`, called by
  `write_file_tool`, `edit_file_tool`, `apply_patch_tool` (every operation, before anything is
  staged, so a patch with one out-of-scope path changes nothing), `create_directory`, `move_path`
  (both ends), and `delete_path`. File-mode changes only happen inside those writes, so they're
  covered. It compares real paths through the turn's `Environment`. An allowed directory that is
  itself a symlink grants nothing. Move and delete resolve only the parent, so a symlink inside the
  checks directory can be removed without following it.
- **Resolution** is `seatWriteScope` in `src/main/mission-control/qa-scope.ts`, called by the
  Process service for seat-bound phase workers and fan-out decomposers. It reads `SeatBinding.role`
  from the run's frozen bindings. The scope is inherited by any subagent the seat spawns
  (`spawn_subagent` and `spawn_subagents`, including write subagents in their own worktrees), so
  delegating can't widen it. Mail-woken turns were already read-only.
- **No folder per user story.** The plan's `<checksDir>/<user-story-slug>/` was replaced: checks are
  shared test code organized by product area (page objects, fixtures, specs), so the QA scope is the
  whole checks directory. A per-story folder would have made every story rebuild its own page objects
  and helpers. A story is traced by its tag `@<feature>.<milestone>.<story>` (`userStoryRef`; feature
  and milestone keys are included because story keys are unique only within a milestone), and
  `109.02` names its manifest `<checksDir>/stories/<storyRef>.json`. The seat's context section
  explains the layout, the follow-the-project's-structure rule, add-don't-rewrite for shared page
  objects, and the tag to use.
- **Scratch directory** is `.mission-control/scratch/<processRunId>/`. It's created at phase start
  with a `.gitignore` of `*`, so the user story commit's `git add -A` never picks it up. A QA seat on
  a milestone run (no single user story, e.g. `reverify`) gets the same two directories and no tag.
- **The seat is told its directories up front** by a `mission_control_write_scope` context section,
  so the `out_of_scope` refusal is a backstop.
- **Default checks directory is `e2e`, not `.mission-control/checks`.** Checks are tests the user
  should find and re-run like any others, so they live in a visible, conventional folder rather
  than a hidden tool folder whose git status depends on the repo. Only the throwaway scratch
  directory stays under `.mission-control/`.
- **Ignored checks directories fail the step.** When a QA step starts in a git repository,
  `git check-ignore` runs on the checks directory. If git ignores it, the step fails (not
  retryable) with a message naming the fix, instead of silently losing the checks.
- **Setting.** `Workspace.missionControl.checksDir` (column `workspaces.mission_control`, schema
  v65). Normalized by `normalizeChecksDir` in `src/shared/mission-control/checks.ts`: the workspace
  root, paths that leave the workspace, and `.git` are refused on save and fall back to the default
  on read. Edited in Feature home → Review setup → Advanced settings → Checks directory.
- **Seeding.** The incremental seeder never touched an entry after first seeding, so an unedited
  QA agent would never have received the new prompt. The manifest now records each single-file
  entry's SHA-256. A changed bundled file replaces the user's copy only when the copy matches the
  recorded hash. Copies seeded before hashes existed are matched against
  `PREVIOUS_BUNDLED_AGENT_HASHES` (the `12e97fa` QA agent). Edited copies are never overwritten.
