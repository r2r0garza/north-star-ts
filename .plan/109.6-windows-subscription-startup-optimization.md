## Objective

Reduce the remaining Windows time to first visible text for Claude subscription inference, and unnecessary setup/model-refresh latency, without weakening private-state checks, managed-policy guards, personal-authentication validation, request isolation or cleanup. Optimize measured bottlenecks rather than promising parity with macOS/Linux or comparing different models, histories and machines as though they were controlled benchmarks.

## Baseline and scope boundary

The user reports Windows manual functionality passing (Docker unavailable in the VM). Initial generation startup launched nine sequential PowerShell processes. Batching reduced that to five; one request-scoped worker now performs the checks in their original order through stdin/acknowledgements, closes before inference and is cleaned up on failure/Stop. No permission/policy approvals are cached. Settings preflight and model discovery retain their one-shot probe implementation.

Installed official Claude Code 2.1.295 synthetic loopback evidence improved from approximately 6.5 seconds with batched one-shot probes to a final text-success sample of 1,733 ms to first delta: environment 4 ms, private directories/worker startup 1,261 ms, compatibility 32 ms, inventory/files/worker close 26 ms, native startup plus loopback response 410 ms. The suite mocks personal authentication and does not measure real upstream service latency. A first delta can be reasoning, not visible text. All 226 enabled subscription tests and 34 installed-loopback cases, typecheck and build passed at that checkpoint; these are not full cross-platform or distribution qualification.

The user reports the worker change is significantly faster, still less snappy than macOS/Linux, but acceptable. Further performance work belongs here rather than reopening 109.2 solely for latency. Existing integrated/package qualification limits remain separate and are not waived. The worker change is already implemented and must not be treated as pending work in this plan.

## Task 1: Establish reproducible latency and process-count measurements

Trace generation, tool continuation, nonstream auxiliary requests, setup preflight and model discovery. Separate environment/executable discovery, private-state setup, policy checks, version probe, auth probe, artifact writes, worker teardown, native initialization/history replay, upstream admission, first response event and first visible text. Extend the existing duration-only diagnostics narrowly; do not log prompts, histories, tool arguments, credentials, account metadata or private paths.

Record warm/cold runs, sample counts, median/tail latency, process counts, Windows architecture, CLI/app versions and native versus emulated execution. Include VM resource constraints without treating the VM as the proven cause. Use official-CLI synthetic loopback first; distinguish mocked-auth timing from actual auth probing and real service measurements. Any cross-platform comparison must document matching inputs and hardware limitations.

**Acceptance:** a repeatable baseline identifies the dominant local startup stages and distinguishes them from network/model delay. Establish a justified improvement target from those measurements before choosing an implementation.

## Task 2: Remove the remaining measured Windows helper overhead

Evaluate direct Windows ACL/registry APIs or a minimal packaged native helper against the existing request-scoped worker. Inspect project build/distribution constraints before adding a native dependency. Keep a single clear implementation, not multiple speculative fallback paths. If measurements do not justify native code, retain the worker and optimize only demonstrated costs. Preserve existing startup ordering: trusted private root before sensitive writes, effective ACL verification before native inference reads, and policy checks around compatibility/authentication.

Preserve owner/effective-access requirements, permitted principals, deny/public access rejection, reparse-point rejection, path confinement, Unicode/space/quoted paths, both registry hives/views, and current fail-closed outcomes. Never disable endpoint protection, add antivirus exclusions, remove policies or reduce permission checks as a performance workaround. Do not introduce a permanently shared privileged PowerShell process.

**Acceptance:** the selected approach measurably reduces local startup latency without changing authorization results or adding unmanaged processes. Document native Windows ARM64/x64 support and package requirements for any new helper.

## Task 3: Optimize setup/discovery and compatibility probes where justified

Assess using the existing request-scoped worker lifecycle for setup and catalog discovery, preserving zero-generation discovery and fixed safe setup guidance. Measure version and official auth probes independently before parallelizing or caching anything. Any proposed reuse must have an explicit bounded lifetime, executable/environment identity, invalidation on CLI/login/config changes and tests showing deterministic failures are not hidden. Do not indefinitely cache ACL, managed-policy or authentication approvals; keep per-request checks unless a separately reviewed equivalent guarantee is demonstrated.

Keep user-owned CLI installation/login, personal-scope restrictions, managed-policy detection, one-upstream-request admission and finite cancellation/timeouts. Preserve manual catalog entries and independent request owners. Do not solve overhead by keeping inference sessions alive, reusing stale canonical history, bypassing the CLI for direct credential access or changing retry budgets.

**Acceptance:** setup, refresh and generation optimizations preserve their existing semantics and demonstrate a measurable benefit. Unjustified caching/parallelism is explicitly declined rather than added speculatively.

## Task 4: Qualify lifecycle, security and perceived latency

Cover cold/warm startup, concurrent same-account requests, tool continuations, auxiliary completions, discovery, Stop during every setup phase, timeout, spawn failure, malformed/oversized worker responses, unexpected exits, early iterator return and app shutdown. Verify no remaining worker/native descendants, sockets, private request files or dangling listeners. Exercise changed/public ACLs, reparse points, Unicode paths, registry policy and changed CLI/auth state; preserve secret-free errors and diagnostics.

Run targeted Windows tests and the installed official-CLI loopback suite before broader provider/host-loop tests, typecheck, build and whitespace/roadmap validation. Use the SQLite wrapper for DB-backed tests and restore Electron native modules. Rerun shared changes on native macOS/Linux; a Windows-only optimization must not slow or alter their execution paths. Qualify the actual packaged Windows runtime separately from Node/dev tests, including any helper resources/architecture handling.

Repeat the controlled measurements from Task 1 and record before/after median/tail latency, process counts and exact artifact scope. Obtain fresh bounded approval before agent-run subscription-backed measurements, counting continuations and auxiliaries. Ask for a user application latency retest; distinguish perceived responsiveness from synthetic timing and upstream variability.

**Acceptance:** reproducible local-startup improvement meets the agreed measurement target, security/lifecycle regressions pass, and the packaged user flow is verified. Document remaining costs rather than claiming API-provider or cross-platform parity without evidence.

## Out of scope

Existing distribution qualification remains deferred, not passed by this performance work.
