# PR109.04: Seat browser and the Mission Control reveal setting

> Status: **DONE** (2026-10-03). Slice 4 of 6 of [`109`](109-qa-seat-verification-capabilities.md).
> Implements product decisions 7 and 8. Lands after `109.03`, whose `app_start` URLs the origin guard
> allows. Where the build differs from the shape below, see **As built** at the end.

## Goal

Mission Control seats can drive the app they're testing in a background browser that's isolated per run
and limited to local origins. A new setting, off by default, lets the user watch.

## Proposed shape

### Wiring the browser into seat turns

- The Process runner (`src/main/tasks/process/service.ts`) and seat sessions
  (`src/main/mission-control/sessions.ts`) pass a `provideBrowser` for seat **`work`** turns only. It
  returns a seat-scoped handle from a new
  `BrowserManager.seatHandle({ conversationId, runId, label, signal })`.
- Mail and answer-only wakes still don't get browser tools. They're already excluded because the tools
  are open-world (`seat-tool-profile.ts`).
- `browser_handoff` is filtered out of seat toolsets. No human is waiting in a headless phase. A login
  wall becomes a seat-comms escalation, or `not_verifiable` with a reason.

### Isolation

- `BrowserSession` takes a partition argument. Seat sessions use a non-persistent per-run partition,
  `agent-browser-seat:<runId>` (no `persist:` prefix). They never share the user's
  `persist:agent-browser` cookies or logins, and parallel seats never see each other's state.
- Seat sessions use `backgroundThrottling: false`, so a hidden page still paints, screenshots, and runs
  timers.
- At phase end (any outcome), the seat's tab is closed and its partition's storage cleared.
- A global cap on concurrent seat browser tabs (default 3). Further browser calls wait for a free slot,
  bounded by the turn's signal, instead of failing.

### Origin guard

- The seat handle's `navigate` allows only loopback origins (`localhost`, `127.0.0.1`, `[::1]`,
  `*.localhost`) plus origins `app_start` returned in this phase run.
- Navigation the page triggers itself (link clicks, redirects, `window.location`) is checked after it
  happens. An off-origin page is replaced with `about:blank`, and the tool result says why.
- Other origins are refused with `toolError("origin_not_allowed", …)` naming the allowed origins.

### Setting: "Show the Mission Control browser when the agent uses it"

- `BrowserSettings` (`src/main/settings/service.ts`) gains `revealMissionControl: boolean`, default
  `false`, loaded and normalized like `revealOnAgentUse`, with preload/IPC passthrough.
- `settings-screen.tsx`: a second switch on the Browser tab, under "Show the browser when the agent uses
  it":

  > **Show the Mission Control browser when the agent uses it**
  > Show a seat's browser tab when a Mission Control agent (such as QA) drives the app it's testing.
  > When off, seat browsers run hidden in the background.

- When on, a seat's tab is created as a visible tab in the **Agent Browser window** (never the sidebar,
  which follows the conversation being viewed), labelled with the seat address and user story
  (`qa@pod-1 · US-12`). The window comes forward on the seat's **first** navigation, not on every one.
- When off, the tab stays homed in the hidden window host.
- Toggling mid-run applies at the seat's next navigation.
- The user can interact with a visible seat tab. The seat's next snapshot reflects the real page, so
  nothing breaks.

### Evidence

- Screenshots a seat takes are also saved to app data at `evidence/<phase-run-id>/`, so proofs can
  cite them as artifacts (`109.05`). Console and network excerpts can be saved there on request.
  Evidence is not written into the checks directory: that's shared test code committed to the user's
  repo, and screenshots and traces would bloat it. App data also outlives the user story's worktree.

### Prompt

- Add the browser workflow to the QA agent prompt (from `109.01`): start the app, snapshot before
  interacting, save evidence, and the local-only rule.

## Tests

- A seat `work` turn gets browser tools without `browser_handoff`. A mail wake gets none.
- Two seats in parallel have separate cookies and storage.
- Origin guard: loopback allowed; `app_start` URL allowed; `https://example.com` refused; an off-origin
  redirect is blanked.
- Cap: a fourth concurrent seat waits, then proceeds when a slot frees; cancel while waiting unwinds.
- Phase end closes the tab and clears its storage.
- Setting: default off (hidden); on → tab appears in the Agent Browser window with its label, revealed
  once; toggling mid-run applies at the next navigation.
- Screenshots land in the evidence directory.

## As built

- **Where things live.** The pool (tabs, origin guard, slot cap, evidence, teardown) is
  `src/main/browser/seat.ts`, behind a small host interface so it's unit-tested without Electron.
  `BrowserManager.seatHandle()` / `releaseSeat()` wrap it. The runner reaches the manager through
  `installSeatBrowser()` (`src/main/mission-control/seat-browser.ts`), the same installer pattern as seat
  sessions.
- **Seat views can't be hidden views.** Chromium never resolves a CDP screenshot of a
  `WebContentsView` that is `setVisible(false)` (measured: it times out), though a *visible* view in a
  never-shown window paints, screenshots, and runs timers, even under other views. So seat views don't
  live hidden in the Agent Browser window as the plan said. They live visible and stacked in a separate
  never-shown window (`ParkedViewHost`, `src/main/browser/parked-host.ts`, destroyed with its last view),
  and a seat's view moves into the Agent Browser window only while it's the tab shown there. A never-shown
  view is also given a 1280×800 size, or its page lays out at 0×0. Conversation tabs had the same bug
  (a background conversation, or the active one while the sidebar panel is closed, couldn't be
  screenshotted), so they now park in the same host and move into the sidebar or the Agent Browser
  window only while shown there (`BrowserManager.placeTabs`).
- **Its own option, not `provideBrowser`.** `runAgentLoop` takes `seatBrowser` instead. `provideBrowser`
  also marks a turn as live (the Auto-mode toggle registry) and lends the browser to CLI providers over
  the MCP bridge; a seat needs neither (CLI seats stay out of scope). Seats get
  `seatBrowserToolDefinitions`, which is the browser toolset minus `browser_handoff`.
- **Only the Process runner wires it.** Seat sessions' own `runTurn` only runs wake turns (consult,
  answer-only), which the seat tool profile already strips of browser tools. User-story-scoped steps
  that run in a seat session go through the Process runner and get the browser there.
- **Per phase run.** The tab, partition (`agent-browser-seat:<phaseRunId>`), and evidence directory
  are per phase run, not per Process run, so parallel seats in one run don't share storage. The tab
  survives the checks step's manifest-repair turns and is released in the phase runner's `finally`,
  after the app's services stop.
- **Origin guard.** Allowed: `about:blank`, http(s) on `localhost`, `*.localhost`, `127.0.0.1`,
  `[::1]`, plus the URLs of services the phase run owns (`ownerServiceUrls`, read live). `app_start`
  URLs are always `http://localhost:<port>`, so that list matters only if a recipe ever returns another
  host. Page-started navigation is stopped *before* the request goes out (`will-navigate`,
  `will-redirect`), and checked again on `did-navigate` (blanked if it got through). Popups are denied.
  The next tool call reports it once as `origin_not_allowed` (all browser tools map
  `OriginNotAllowedError` through `browserFailure`).
- **Cap.** A slot is taken when a seat first needs its tab, not when the turn starts, so a seat that
  never browses never waits. Closing a tab mid-phase (`browser_close`) frees the slot. Release fails
  any call still waiting for that phase's slot.
- **Reveal.** The window lists visible seat tabs in italics after the conversation tabs (the app's
  sidebar never does). While a seat tab is shown, the URL bar, reload, Pick, and close are disabled:
  they act on conversation tabs. The user can still click around in the page. In window mode,
  switching conversations in the app takes the window back to the conversation tab.
- **Evidence.** Screenshots save as `evidence/<phaseRunId>/screenshot-NNN-<time>.jpg` under app data,
  and the tool result gives the path. `browser_console` and `browser_network` take `save_evidence:
  true` (a no-op with a note outside seats).
- **Prompt.** A `## Your browser` context section goes to every seat step that gets a seat browser
  (local-only, wiped at the end, no takeover, cite screenshot paths). The QA agent prompt gains a short
  "Driving a UI in the browser" part.
- **Verified in Electron.** A scratch run of the real `BrowserManager` (settings stubbed) passed:
  hidden-seat screenshot, snapshot, click; cookie isolation between seats and from
  `persist:agent-browser`; refusal of a public URL, an off-origin 302, and an off-origin link click;
  reveal, then the user switches the window away and the seat still screenshots; toggle off; storage
  cleared on release; the seat host window gone after the last seat.
- **Found in passing, not fixed here.** The same hidden-view limit applies to *conversation* tabs: a
  background conversation's tab is `setVisible(false)` in the Agent Browser window, so a
  `browser_screenshot` from that conversation's turn should time out the same way.
