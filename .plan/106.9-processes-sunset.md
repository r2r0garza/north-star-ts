# PR106.9: Processes sunset — import as playbooks, hide the sidebar button

> Status: **PLANNED**. Final slice of `106`. Once Mission Control reaches parity, hide the **Processes**
> sidebar button (behind a setting, reversible), and give every existing Process a one-click path into
> Mission Control as a playbook. The Process **engine** stays: it's the playbook runtime. Nothing is
> deleted.

## Goal

Users who built Processes lose nothing. The sidebar gets simpler, and the new model is where new work
starts.

## Parity checklist (all must hold before the button is hidden by default)

- [ ] Every Process capability is reachable through a playbook: agent and role pools, dispatch routing,
      fan-out, on-each-subtask, gates, validators, rework, flag-back, sub-processes, command phases
      (`104`), required skills (`105`), runtime overrides (`083`), and dot folders (`030`).
- [ ] A one-off "just run this playbook against an objective" path exists (see decision 3), so ad-hoc
      Process runs without an initiative still work.
- [ ] Existing Process runs (history and in-flight) remain viewable and controllable.
- [ ] Process import/export (`037`) continues to work, including role-bound phases (formatVersion 2).
- [ ] Mission Control has been used for real work across at least three initiatives, and the `106.3`
      evaluation question ("is seat-bound execution clearly better?") was answered yes.

## Product decisions

1. **Import as playbook.** From a Process (in the legacy screen or a Mission Control picker): "Use as
   slice playbook." This creates a `playbooks` row (altitude `slice`, hook `run`) pointing at the **same**
   `process_definitions` row. There's no copy, so edits stay in one place. An optional "Convert agents to
   seat roles" wizard maps each distinct agent name to a role (suggested from the agent name) and
   rewrites the phase-agent rows to `seat_role`. It warns if the chosen rig lacks those roles.
2. **Hide, don't remove.** A setting "Show legacy Processes in sidebar" (default **off** after this
   slice ships, on before). With it off, the button is hidden, deep links still work, and a "Processes"
   entry appears in Mission Control's Playbooks tab as "All process definitions."
3. **Quick run.** Mission Control gains **Quick run**: pick a playbook (or any process definition) + a
   workspace + an objective → runs it as an ordinary Process run with no initiative, using an ad-hoc
   "solo" binding (roles bound to the agents named in a small picker). This replaces the legacy screen's
   primary action, so hiding the button doesn't remove a workflow.
4. **Run history.** Legacy Process runs show in Mission Control under Playbooks → History, using the
   existing monitor component. Runs started from Mission Control link back to their initiative/slice.
5. **Chat entry points.** Any chat surface that starts a Process run (slash commands, task producer
   `015`) keeps working unchanged. Copy that says "Process" is updated to "playbook" only where it's
   user-facing and the change doesn't break stored identifiers.

## Implementation plan

1. Parity audit: walk the checklist, file gaps as `106.x` follow-ups; don't hide the button until green.
2. "Use as slice playbook" action + role conversion wizard (+ tests for XOR validity after conversion).
3. Quick run in Mission Control (+ solo binding).
4. Playbooks → History view (reusing the Process monitor).
5. Setting + sidebar visibility (`settings-screen.tsx`, `sidebar.tsx`), with the default flipped in this
   slice.
6. Update `README.md` and in-app startup guide copy; mark `026`'s screen as legacy in its plan header.

## Acceptance criteria

- With the setting off, the sidebar shows no Processes button, and every Process workflow (author, run,
  monitor, approve, import/export) is reachable from Mission Control.
- Turning the setting on restores the legacy screen exactly.
- An existing Process imported as a playbook runs identically in Quick run and inside a slice.
- No Process data is migrated destructively; downgrading the setting loses nothing.
- `pnpm typecheck`, full test suite, and `pnpm build` pass.
