# PR106.8: Health — ceremony vs progress, loop detectors, alerts, auto-pause

> Status: **PLANNED**. Eighth slice of `106`. Instruments Mission Control like any other software
> ("Agent Productivity Monitoring"). Every durable event is classified as **progress** or **ceremony**,
> detectors watch for known coordination pathologies, and alerts go to the user *and* to a seat that has
> the context to analyze them. Adds a **Health** tab.

## Goal

The user knows when to step in without watching every transcript. The main signal: **ceremony keeps
rising while progress stays flat.** The team is busy, but the map isn't moving.

## Event classification

A single `mc_events` append-only table (or a view over existing tables where the data already lives)
with `initiative_id, mission_id?, slice_id?, seat_address?, class, type, weight, created_at`.

| Progress (moves the map) | Ceremony (ritual around the work) | Neutral |
|---|---|---|
| slice → done / merged | messages sent, replies | worker turn started |
| proof accepted | directions delivered | tool call (read) |
| mission completed | validator rounds, rework rounds | |
| merge landed | proof recorded but rejected / proof edits | |
| acceptance criterion met (first time) | approvals requested | |
| hook completed with output | plan revisions, proposals created | |
| | refocus deliveries, escalations | |

Weights are constants in `src/shared/mission-control/health-weights.ts` (tunable; tests pin the
defaults). Emission happens at the existing write sites (work-state transitions, comms bus, proof
service, merge queue, navigator), via one `recordEvent()` helper. Nothing parses transcripts.

## Metrics (rolling windows: 15 min, 1 h, run lifetime)

- **Ceremony ratio** = ceremony weight / max(progress weight, ε), per initiative, pod, and seat.
- **Time since progress** per initiative and per running slice.
- **Throughput**: slices merged per hour; wave completion time vs median.
- **Budget burn** (from `106.6`).

## Detectors (each emits a `health_signal` with evidence ids)

| Detector | Pathology (from the transcript) | Default trigger |
|---|---|---|
| `ceremony_rising` | bureaucracy | ratio (1 h) > 6 and rising across 3 windows, with no progress event in 30 min |
| `stalled` | stuck coordination loop | running initiative, no progress event in 45 min, and ≥ 1 active worker |
| `proof_polishing` | recursive proof loop | proof-related activity after acceptance, or ≥ 3 rejected proof revisions across attempts |
| `ping_pong` | coordination loop | ≥ 6 alternating messages between the same two seats in one thread with no progress between |
| `scope_drift` | moonbase | slice diff touches > 2× files of its touch hints, or files outside hints > threshold, or ≥ 3 follow-ups proposed in one slice |
| `approval_by_proxy` | just following orders | a seat asks another seat to "approve"/"authorize" (lightweight keyword + kind check) where the target lacks the relevant decision right |
| `refocus_ignored` | persistent drift | a drift signal fires again within N turns after a Refocus for the same slice |
| `retry_churn` | thrash | a slice consumes all attempts, or the same failure reason repeats |

Detectors are pure functions over the event stream + DB state (`src/main/mission-control/health/`),
evaluated on each Navigator tick and on a 60 s timer while an initiative is active. Each detector is
unit-tested with synthetic event sequences, positive and negative.

## Alerts and responses

Severity levels: **info** (Health tab only), **warn**, **critical**.

- **warn** → user notification (existing toast / OS notification path). Also a `kind=alert` message
  to the **context-bearing seat**: the lead of the pod where the signal originated (or the overseer's
  lead), never an arbitrary seat. The alert includes evidence and asks for a short analysis plus one of:
  continue / replan (via tools) / escalate. It also triggers a Refocus (`106.7`) on the offending seat
  session.
- **critical** (`stalled` > 2× threshold, `refocus_ignored` twice, `retry_churn`, or any warn unresolved
  for 30 min) → **auto-pause** the initiative (`106.6` pause semantics) and notify the user with the
  evidence summary.
- Alerts are deduplicated per (detector, anchor) with cooldowns so the alerting itself doesn't become
  ceremony. Alert messages count as ceremony but are excluded from the `ceremony_rising` numerator to
  avoid feedback loops.
- Thresholds are per-initiative settings with sane defaults; each detector can be muted per initiative.

## UI: Health tab

- Top: initiative health status (Healthy / Watch / Degraded / Paused-by-health), progress vs ceremony
  sparkline (1 h and lifetime), time since progress, and budget burn.
- Signals table: detector, severity, anchor (slice/seat/pod), first/last seen, status (open /
  acknowledged / resolved / muted), and "evidence" drill-down listing the concrete events (message
  links, proof revisions, files outside hints).
- Per-pod and per-seat breakdown: ceremony ratio, messages, progress events, and time in `busy`.
- Slice and mission views show a small health dot when a signal is anchored there.

Follow `dataviz` conventions for the sparklines (both themes, accessible colors).

## Implementation plan

1. Event model + `recordEvent()` + emission at all write sites (+ tests asserting each transition emits
   exactly once, including under crash replay).
2. Metric computation over windows (pure, tested).
3. Detectors + signal lifecycle (open → acknowledged / resolved / muted), dedupe, and cooldowns.
4. Alert routing to the context-bearing seat + user notifications + auto-pause on critical.
5. Refocus hook integration (`106.7` drift interface).
6. Health tab and anchored dots.

## Acceptance criteria

- A scripted run where two seats exchange messages without progress raises `ping_pong`, alerts the pod
  lead (not a random seat), triggers Refocus, and escalates to auto-pause if it continues.
- A slice that keeps editing its proof after acceptance raises `proof_polishing`.
- A normal healthy scripted Autopilot run raises no warn/critical signals (false-positive guard).
- Alert messages don't trigger `ceremony_rising` by themselves.
- `pnpm typecheck`, focused tests, and `pnpm build` pass.
