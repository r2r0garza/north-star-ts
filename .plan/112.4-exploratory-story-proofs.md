## Goal

A story's QA proves each criterion by driving the running app in its own isolated browser and saving
evidence. A proof that rests only on the builder's tests or on reading code is refused. Before QA starts,
the harness checks that the app runs. If it doesn't, that goes to recipe repair, and the story's QA
attempt isn't spent on it.

## Part 1 — App check before the `test` step (needs `104`)

- An engine-owned **app check** runs before the story playbook's QA proof step: `verifyRecipe` (`112.3`)
  in the story's worktree, at its current commit, skipped when the state is already `verified` for that
  commit. No LLM call.
- **Form:** a built-in kind of `104`'s deterministic phase (an `app_check` alongside `command`), so it
  appears in the run monitor with a receipt (stages, durations, smoke results, log tail) and settles
  exactly once, the way `104` specifies. It isn't a user-authored command, so the builder shows it as a
  fixed step with no command editor.
- **Placement:** the shipped default story playbook becomes **Spec → Build → App check → Test**.
  Stored playbooks are user data and stay as they are, so the app check also runs **implicitly** before
  any Mission Control story's QA proof step when the playbook has none, keeping the protection
  independent of playbook edits.
- **Outcomes:**
  - passes → the `test` step starts. The services stay up, owned by the test step's phase run (the app
    check hands ownership over instead of stopping and restarting);
  - fails with class `environment` → `112.3`'s repair loop, then escalation. The `test` step doesn't
    start and no proof revision or story attempt is burned. If unresolved, the story ends *unverified*;
  - the project has no services (scenario 5) → passes trivially, and QA proves by commands.
- **Reset to default** (`backup:109.02`'s `diffPlaybookWithDefault` / `resetPlaybookToDefault` in
  `playbook-defaults.ts`, IPC `missionControl:playbooks:defaultDiff` / `resetToDefault`, and the picker's
  confirm dialog) isn't on main. Port it so existing installs can take the new default after seeing the
  diff.

### Wiring

- Only the Process runner wires it (`service.ts`): a seat's `work` step on a builder or QA role gets a seat
  browser, bound to its phase run, with `allowedOrigins: () => ownerServiceUrls(phaseRun.id)`. Released
  in the phase `finally`, after `stopServices`.
- Origin guard: `about:blank`, http(s) on `localhost`, `*.localhost`, `127.0.0.1`, `[::1]`, plus the phase
  run's service URLs. Navigation is stopped before the request (`will-navigate`, `will-redirect`) and
  re-checked on `did-navigate`; popups are denied.
- `112.3`'s smoke load may switch to the seat browser here, if the scorecard shows a difference from the
  headless Playwright load. Otherwise keep the runner.

## Part 3 — Proof methods (`backup:109.05`, as revised by `backup:110.04`)

- `record_proof` criteria gain a required `method`: `app_exercised | command | builder_tests | code_read`.
  `qa_check` (109.02's per-story checks) isn't ported. `command` cites a `104` command phase through the
  `commandPhaseKey` field main's `proof.ts` already accepts.
- Rules in `src/main/mission-control/proof.ts` (pure, with a resolved `ProofVerification` built by
  `recordUserStoryProof`, listing every problem at once so one resubmission fixes them; a refusal
  doesn't use a revision):
  - `code_read` is never `met`. Record `not_verifiable` with a reason.
  - **`builder_tests` alone is refused** for `met` (stricter than 109.05, which only warned; `112`
    requires it). Builder tests may support a criterion proven another way.
  - `app_exercised` needs at least one artifact in `evidence/<phaseRunId>/` (absolute or relative to it;
    symlinks out don't count).
  - `not_verifiable` because the app couldn't run → the story is *unverified* (`112.3`), not rejected.
- `UserStoryProof` stays `version: 1`. Old proofs without `method` show **Unspecified**.
- **Health:** port the `weak_proof` detector (`info`, no auto-pause) for accepted proofs with criteria met
  only by `builder_tests` or with no method (proofs from before this slice).
- **Proof view** (`proof-panel.tsx`): a method badge per criterion, screenshots as thumbnails, other
  evidence by name. IPC `missionControl:evidence:read` / `open` refuse anything outside the evidence root.

- Replace `PROOF_STEP_INSTRUCTION` (`service.ts`, "run the tests or commands, read the code") for Mission
  Control story proof steps with the backup's exploratory kickoff (`exploreStepNote`, `backup:110.04`):

- Bundled QA agent (`agents/qa-agent.agent.md`): one sentence on exploring with evidence, no tool names
  (users' edited copies get the rules through the kickoff).

## Tests

- App check: runs before `test`; skipped when verified for the commit; environment failure → repair, no
  revision or attempt burned; unresolved → *unverified*; no-services project passes; implicit app check
  for a stored playbook without one.
- Seat browser: the backup's `seat.test.ts` and manager tests (isolation between seats and from
  `persist:agent-browser`, off-origin refusal including a 302 and a link click, slot cap, release clears
  storage); a hidden seat can screenshot.
- Proof rules table: each method, refusals listed together, `builder_tests`-only refused, evidence must
  live in the phase's directory, old proofs load.
- Write scope: QA can't write product files; a subagent inherits the scope.
- `user-story-execution.test.ts`: a three-plus-one-step run accepted with exploratory evidence; refused
  with builder tests only; refused without a screenshot.

## Acceptance

- Scenario 6: a story whose builder misread a criterion is **rejected on exploratory evidence**, even
  though the builder's tests pass.
- Proofs citing only builder tests or code reading are refused.
- An environment failure at the app check never reaches QA as a rejection, and the scorecard shows zero
  story attempts burned by it.
- Manual check in the running app: a seat browser screenshots while hidden, and the user can reveal it
  in the Agent Browser window and watch.
